# AI Leverage Log

I used ChatGPT as a design and pressure-testing partner, and Codex for implementation, testing, and code review. Early on, I used ChatGPT to break the prompt into a requirement matrix so I could make sure I was addressing what was actually being asked without overbuilding the prototype. We worked through several architectural decisions together, including where to separate the shared triage pipeline from category-specific policy, how to preserve the existing manual support workflow as the safety net, and why the take-home prototype could stay synchronous even though I would use an asynchronous, queue-backed design in production. One of the most useful exercises was assuming the classifier could be confidently wrong about a compliance complaint. That pushed me away from relying on model behavior alone and toward an independent safety check plus a final egress guard. I also used Codex to challenge whether simply returning human_approval_required=true was enough to satisfy the human-in-the-loop requirement. I agreed that it was not, so I added an explicit release gate while deliberately leaving the existing member-send mechanism outside the scope of the prototype.

I kept the consequential design decisions as my own: using Go, keeping the existing case system as the source of truth, routing Compliance/Legal cases directly, using category-specific confidence thresholds, failing closed to the manual workflow, and treating new categories as configuration when they use an existing action primitive. AI was also useful as a reviewer rather than just a generator. During implementation review, I caught that an early routing path performed the external route before writing the audit record, which violated the fail-closed behavior I wanted, so I changed the ordering and added a test proving an audit outage results in zero automated routes. After the implementation was green, I asked Codex to review it adversarially instead of assuming passing tests meant the design was complete. That surfaced two gaps I had not originally tested for: the release gate trusted caller-supplied decision content, which allowed a modified draft to potentially be treated as approved, and the sanitizer did not catch several realistic sensitive-data formats such as formatted SSNs, emails, and account or routing values. I reproduced those failures before fixing them, then tightened the underlying boundaries rather than just patching the individual test cases. That same review also caught an edge case where NaN confidence could bypass a normal threshold comparison and reach the drafting path. With more time, I would continue using AI primarily to generate adversarial cases and challenge these safety assumptions rather than expanding the prototype with more features.
