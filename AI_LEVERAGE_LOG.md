# AI Leverage Log

I used ChatGPT as a design (Codex for implementation/testing) and pressure-testing partner. I first had it decompose the prompt into a requirement matrix so I could separate explicit constraints from attractive but unnecessary scope. We then compared design options for the shared-pipeline/category-policy seam, preserving the existing manual workflow as a safety net, synchronous prototype vs. asynchronous production execution, and data-minimized routing. The most important pressure test was intentionally assuming the classifier could be confidently wrong on a compliance complaint; that drove the independent safety detector plus final egress invariant rather than trusting model classification or prompting. I also used Codex to challenge whether `human_approval_required=true` was enough to model human-in-the-loop. I accepted the recommendation to add a small explicit release gate, but kept the existing member-send mechanism out of scope: the gate releases only an eligible General Q&A draft after a matching human approval is durably audited, and it still refuses a Compliance decision even if an approval is supplied.

I kept the consequential architecture choices human-owned: Go, the existing case system as source of truth, direct Compliance/Legal routing, category-specific confidence thresholds, configuration-driven extension when an existing action primitive is sufficient, and fail-closed behavior. I also overrode an AI-generated implementation detail during review: the first routing path performed the external route before the audit write, which violated the agreed fail-closed boundary. I moved the sanitized pre-execution audit ahead of the routing side effect and added a test proving an audit outage causes zero automated routes. The CI suite now also forces a 99%-confident wrong General Q&A classification for a compliance-sensitive intake, verifies safety still wins with no member draft, verifies sensitive account data cannot enter Product routing or audit records, and verifies approval/release behavior. With more time, I would use AI to generate adversarial intake variations and failure scenarios against these invariants rather than expanding feature breadth.
